Build a production-quality, containerized lab application for demonstrating Thales CADP Application Integration.

IMPORTANT:
This is a hands-on integration lab. Do NOT build only a collection of scripts or mock functionality. Build a real working web application with a .NET backend, a browser-based web interface, containerization, configuration through environment variables, logging, test support, and clear documentation.

The application must integrate with a real CADP environment. Do not hard-code or invent CADP protocol messages. Any CADP/NAE-XML request format must follow the approved Thales documentation/configuration supplied to the project.

============================================================
1. LAB REQUIREMENT
============================================================

The mandatory lab requirement is:

"Build a .NET string/file encryption client with safe streaming; use PyKMIP or another client to create/get/locate/activate/revoke test keys; build a TLS TCP client for approved NAE-XML key and crypto requests; execute negative tests without hard-delete."

Required submission:

"Three source packages with READMEs, sequence diagrams, test vectors, operation-state matrix, logs and failure matrix."

The application must therefore demonstrate:

1. .NET string encryption/decryption
2. .NET file encryption/decryption
3. Safe streaming/chunk processing
4. KMIP key lifecycle operations
5. NAE-XML over TLS/TCP
6. Key requests
7. Crypto requests
8. Positive tests
9. Negative tests
10. Key revocation without hard-delete
11. Logging and evidence
12. Web-based interface
13. Containerized deployment

IMPORTANT:
Implement SAFE STREAMING.

Do NOT use:

File.ReadAllBytes()

for arbitrary file sizes.

Do NOT load an entire file into memory.

Use streaming APIs:

Stream
FileStream
BufferedStream
CryptoStream where appropriate

Process data in chunks.

Example conceptual flow:

Input File
    |
    v
Read Chunk
    |
    v
Encrypt
    |
    v
Write Chunk
    |
    v
Repeat
    |
    v
Finalize
    |
    v
Output File

The application must correctly handle:

- empty files
- small files
- medium files
- large files
- binary files
- files containing Unicode text
- interrupted operations
- corrupted ciphertext
- insufficient permissions
- invalid key identifiers

Ensure finalization/tag/metadata handling is correct for the selected algorithm/protocol.

Do not assume that independently encrypting arbitrary chunks with the same IV is safe.

Streaming must respect the actual CADP cryptographic API/protocol semantics.

14. NAE-XML TLS CLIENT
============================================================

Implement an NAE-XML client using a TLS TCP connection.

The client must:

1. Resolve configured CADP/NAE endpoint
2. Open TCP connection
3. Establish TLS
4. Validate the server certificate
5. Authenticate using the approved mechanism
6. Construct an approved NAE-XML request
7. Send request
8. Receive response
9. Parse response
10. Display structured result
11. Handle protocol errors safely
12. Close connection correctly

Do NOT invent an XML protocol.

Do NOT assume request names, namespaces, authentication formats, framing, or cryptographic operations.

Create an abstraction such as:

INaeXmlClient

with methods appropriate to the approved NAE-XML interface.

For example conceptually:

ConnectAsync()
AuthenticateAsync()
SendRequestAsync()
ParseResponse()
CloseAsync()

But adapt the actual implementation to the approved Thales NAE-XML protocol documentation.
